# WO-154: voice chat off by default -- how the launcher decides

From 0.45.0 the mod's voice chat is off unless the player chose to turn it on: a new install, and any player who never picked a voice setting, starts with no microphone opened, nothing captured or sent, and nothing started at session start; it stays one click away in the launcher's Settings and in the mod menu. The launcher cannot tell a player who chose "on" from one who never chose: until 0.44.0 every save wrote `"VoiceChatEnabled"` into settings.json with the default `true`, so a stored `true` looks the same either way. It therefore decides with a second key, `"VoiceChatChosen"`, which is written only when the player picks a value (the launcher's Settings checkbox, or the mod menu's switch, which the agent writes into the same file), and treats voice as on only when both `"VoiceChatChosen"` and `"VoiceChatEnabled"` are `true`; a missing `"VoiceChatChosen"` reads as `false`. An upgrade never changes the stored `"VoiceChatEnabled"`, and `"VoiceChatChosen": false` is only added when the launcher writes the file for another change the player made. The consequence, accepted on purpose: a player who had chosen voice on before 0.45.0 finds it off after the upgrade and turns it on once again; after that the choice is kept. The launcher always starts the agent with `--voice` or `--no-voice`, so no default elsewhere decides it (`KcdMp.Wire.VoiceSetting`, `KCDMP_launcher/Models/AppModels.cs`, `dotnet/KcdMp.Client/GameBridge.Wo154Voice.cs`).
